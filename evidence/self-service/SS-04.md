## Verification

### `test/self-service-documents.e2e-spec.ts` — 13/13

Fixtures (all created by the spec): an opted-in and a non-opted-in company; me, a same-company
colleague, an outsider, a terminated employee; MY documents in every state (3 available with
different expiries, pending, quarantined, deleted), a colleague's, a company-level one
(`employee_id NULL`), an outsider's. One document has a **real blob in MinIO**.

| Test | Result |
|---|---|
| list | exactly `[soon, later, no-expiry]` in that order; none of pending / quarantined / deleted / colleague / company / outsider ids anywhere in the body |
| pinned fields | `{documents}` → exactly `category, contentType, expiryDate, fileName, id, issueDate, title`; no `storageKey`, `legalHold`, `uploadedByUserId`, `sizeBytes`, `status`, `clientId`, `employeeId`, `createdAt`, or storage-key prefix |
| **download** | `{method: 'GET', expiresInSeconds: 300}`; **fetching the URL returns status 200 and bytes identical to the uploaded blob** |
| 404 — same response for all | colleague's (same company) · company's · another company's · my pending · my quarantined · my deleted · unknown uuid · `not-a-uuid` |
| company not opted in | 403 on list and download |
| terminated | 403 |
| staff / client rep | 403 (list and download); unauthenticated 401 on both |

**Proven to bite — and what it showed:** removing `status: 'available'` from
`getForEmployee` → exactly **3 failures** (my pending / quarantined / deleted became
downloadable). In the same run the colleague's, company's and outsider's documents **still
returned 404** with the application filter gone: the database fence (SS-02) alone kept them
out. Two layers, each doing its own job. Restored → 13/13.

### Isolation harness — 18/18

`GET /me/documents` joins the colleague loop (my response contains my id via my fixture
document's title; the colleague's does not; unauthenticated 401); new `employee-read` loop
(download unauthenticated → 401); the principal fence stays green.

### Full suite — 429/429

429 = 412 + 13 (new spec) + 4 (harness: 3 list probes + the `employee-read` loop). Eight full
runs: **six clean**; two had ONE failure each, in unrelated tests that pass alone:

- vacancies "a client rep reads ONLY their own client vacancies" — a controller SS-01 touched,
  so not waved off: **5/5 green alone**, and its companies are created by that spec (no data
  shared with others); message not captured on that run.
- client-users ISOLATION test — captured: **`Parse Error: Expected HTTP/, RTSP/ or ICE/`**, the
  documented supertest ephemeral-port signature (REP-04 note).

The suite grows each card, and so does this flake's surface; the harness fix filed in REP-04
is worth scheduling.
