### API

- Full suite **473/473 ×3** (475 − the two `self` routes that intentionally left the
  employee-must-403 list).
- **A false alarm worth recording.** The first targeted run reported the principal fence failing
  with `GET /config -> 200` for an employee. `GET /config` requires `config.read`, which the
  employee role does not hold, and `PolicyService.can` is exact — and it did **not** reproduce:
  isolation alone 3 × 21/21, the same four-spec combination 5 × 64/64. Consistent with the
  documented supertest ephemeral-port flake (REP-04 recorded the same class: "unauth `GET
  /documents` → 200"), where a response from another app instance lands on the wrong socket.
  The worrying corollary: **that flake can manufacture a security failure — or mask a real one**
  behind another instance's 403. The REP-04 harness fix is now more than hygiene.
