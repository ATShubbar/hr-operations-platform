- Date: 2026-10-11
- Status: **done**

## What changed

`components/notification-centre.tsx` replaces `notification-bell.tsx` behind the header bell.

| Part | What it shows |
|---|---|
| Bell | A red count: unread items that need action plus unread updates |
| Header | "Notifications" and "Raised by the escalation ladder, not by activity."; **Mark all read** for the tab in view, shown only when something there is unread |
| Tabs | Needs action · Assigned to me · Everything · **Updates**, each with its count |
| Ladder tabs | Items grouped by stage, most urgent first (Breach · acting now, Escalated, Reminder, Notice). Each item: what it says, who it is about, "client · owner · rule", a days chip, and the date. A coloured rule down the side by stage, a red dot while unread. Twelve per stage, then "N more at this stage". |
| Updates tab | Today's events, exactly as the bell listed them |
| Footer | "9 expiries are already being renewed in the work queue, so the ladder stays quiet on them." |

Clicking an item marks it read and goes to where it is acted on:

| Item | Opens |
|---|---|
| A person's document | their record, Documents tab |
| A dependant's document | the sponsor's record, Family tab |
| A request | that request |
| A procedure or task | the work queue with **that item's dialog open** |

The last row needed one addition: the work queue now opens an item named in the address (`/queue?open=procedure-<id>`). Closing the dialog removes it from the address, so the same link works again.

Someone without the ladder (client managers and employees, until NC-05) gets the Updates list alone, with no tabs, as the bell was. The page makes no ladder request for them.

## Fixed while checking

- **The days chip read "employees.over".** I had taken the wording from the wrong namespace. It now reads "8d over".
- **The four tabs wrapped onto two lines** at the prototype's 428px. The pills are slightly tighter; measured 397px of the 408 available.

## Stated plainly

- **The fourth tab is the deviation you chose.** With it the tab row is fuller than the prototype's.
- **The small line under the days chip shows the date**, where the prototype shows a work reference. Our ladder items have no reference of their own.
- **The count on each ladder tab is the number of items in it**, read or not, as in the prototype. Only the bell counts unread.
- **Nothing here has an automated test.** The panel is screen code over the tested API; it was checked by hand as above.
- **The "Escalation rules" button is not in the footer yet.** It arrives with NC-04.
- The test browser's screenshots lagged behind the page more than once. Every result above was read from the page or the API, not from a picture.
