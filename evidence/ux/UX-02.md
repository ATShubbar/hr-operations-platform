## Scope change I made, and why

**`DirectionProvider` was pulled forward from UX-03b into this card.** Base UI's
docs state it "does not affect HTML and CSS" — `dir` on `<html>` handles the
pixels — but that components need it to adjust *behaviour*: arrow-key direction in
a select, which side a popover aligns to, swipe dismissal. Base UI does **not**
read `dir` from the DOM, and portalled popups sit outside the element carrying it
regardless.

Shipping a new portalled Popover into that hole would have been knowingly adding
a broken RTL surface. Three lines in a provider vs. a known defect in the primitive
this card exists to deliver — I moved it rather than sequence around it. The bidi
*isolation* work (identifiers, dual-calendar dates) stays in UX-03b.

Worth stating plainly: this was a **latent bug on every screen since the first
Select landed**, and Arabic is the default locale — so the app has been shipping
LTR-handed keyboard behaviour to its primary audience.

## StatusPill: why it is not Badge

Deliberately a separate component. `Badge` is arbitrary metadata whose colour is
decorative — a brand-gold "New" badge is legitimate. A status pill answers "what
state is this record in", so its colour carries meaning and must come from the
`--status-*` tier. Merging them is what produced the inconsistency the audit
found: `terminated` and `on_leave` sharing a grey, `resolved` solid but
`completed` outlined, every audit action rendered in brand gold.

This is also exactly the line the UX-01 lint rule draws, so the two decisions
reinforce each other rather than needing to be remembered separately.

**Three encodings, never one:** tone (colour), a dot (shape), and the label. The
dot draws from `--status-<tone>` at 6.0–8.9:1 against card — the decorative
hairline is far too light to carry it, by design (UX-01 finding).

### The tone table

`lib/status-tone.ts` maps seven domains onto five tones. Two judgement calls in it:

- **`suspended` is `warning`, not grey.** The audit found all three non-active
  employee states collapsed into one grey, so a suspended employee looked identical
  to one on holiday.
- **Candidate stages get one tone, not seven.** The pipeline board already encodes
  progress by lane position; colouring seven stages spends the channel twice.
  `info` for everything in flight, `ok` only at hired, `critical` only at rejected.

## Adoptions (only where they are a strict improvement)

I did **not** sweep all fifteen screens — that would mix a primitives card with a
migration. Three adoptions where the change is unambiguously better:

### 1. The expiry dashboard — and it fixed a real defect

`expired` and `d7` were **both** `destructive`, so an already-expired document was
visually identical to one due in a week — the two states that most need telling
apart. Now:

| Bucket | Was | Is |
|---|---|---|
| Expired | `destructive` (red) | **critical** — red |
| Next 7 days | `destructive` (red, identical) | **warning** — orange |
| Next 30 days | `default` (brand gold) | **neutral** — grey |
| Next 60 days | `secondary` (grey) | **neutral** — grey |

This is the UX-01 six-tiers-to-three-severities decision landing on a real screen.
The 30/60-day buckets are awareness-only for most staff, so they get no colour:
spending a hue on something nobody will action today is what trains people to stop
reading the ones that matter. Verified live with temporary dates that put documents
in both severities — screenshot shows red **Expired** beside orange **Next 7 days**,
each with its dot. Dates restored afterwards.

### 2. The notification bell → Popover + Skeleton

The hand-rolled panel had a `mousedown` listener and nothing else. Measured before
and after, in the browser:

| | Hand-rolled | Base UI Popover |
|---|---|---|
| `aria-expanded` | absent | **`true`** |
| `aria-haspopup` | absent | **`dialog`** |
| Escape closes | **impossible** | **closes** |
| Focus returns to trigger | no | **yes** |
| RTL collision handling | none (`end-0`) | **0px overflow at a 472px viewport** |

That last row is the one that mattered: in RTL the bell sits at the *left* edge, so
a 320px panel anchored `end-0` opened toward the viewport boundary with nothing to
push it back. Base UI's Positioner shifts it — measured `left: 147, right: 467` in
a 472px viewport, entirely on screen.

Loading also went from a bare "Loading…" string to a skeleton in the shape of the
list, wrapped in a polite live region so a screen reader hears something.

### 3. Both hand-rolled textareas → `Textarea`

Requests and Tasks had the same class string copied inline. No visual change; one
fewer place to drift.

## Two design rules encoded in the primitives

**Skeleton runs a finite pulse.** Three iterations, then it settles into a static
placeholder. An indefinitely looping animation over five seconds needs a pause
control to be conformant, and a shimmer nobody can stop is irritating on a screen
someone stares at all day. Gated behind `motion-safe:` as well.

**Toast is Base UI, not Sonner, and is passive-only.** This app is
shadcn-on-Base-UI; Sonner brings a second portal/focus/animation system and an RTL
story built on direction-swapped *physical* CSS properties. Base UI's viewport is a
landmark region reachable with F6 and its action is a real focusable button — most
toast libraries announce via a live region and leave the action unreachable by
keyboard. Encoded in the API:

- `toastSuccess` is polite and auto-dismisses; `toastError` is assertive and
  **never** auto-dismisses.
- Anything carrying an action gets `timeout: 0`. An "Undo" that vanishes on a timer
  is a control keyboard users can't reach in time.
- The header comment records the rule that **every consequential outcome also lands
  in the notification bell** — that durable twin is what makes the transient one
  conformant, and we already built the bell.
