## The bug this card found — every government-data expiry edit returned 500

**The trigger:** the first Renew failed with "Could not record the renewal". The same request
by hand returned **500**, and the API log showed `PrismaClientValidationError`.

**The cause:** the government-data write schema was `govdataGroupSchema.partial()`, the
**response** schema, whose expiry fields are plain `z.string()`. A date-only value
(`"2027-10-27"`) reached Prisma unconverted, and Prisma rejects it.

**Why it went unnoticed:**
- This has been true since EMP-02. The old government-data dialog sent exactly this shape.
- Nothing tested an expiry write.
- GRO-03's write-back passes `Date` objects, so it never hit the bug.

**The fix:** `.extend({...: z.coerce.date().nullable()})` for `iqamaExpiry`, `passportExpiry`,
`workPermitExpiry` and `exitReentryExpiry`, in the contract, so create and update both benefit.

**The proof:**
- The new test was **red first** (500), then green.
- Employees spec 12/12.
- Full API suite **484/484** (483 + 1).

**Also affected:** DS-06's Profile tab edits these same fields, so its expiry edits now work too.

## Bugs caught while verifying

1. **Every government-data expiry edit returned 500.** Pre-existing since EMP-02; fixed in the
   contract, with a test proven red first (above).
2. **The fixed columns rendered at 143/95/234.** With the flexible columns sized as percentages,
   a fixed-layout table spread the remainder into ALL columns. They are now unsized and take
   the rest, so 132/88/216 is exact.
3. **"Not on file" for a contract with a scanned, dated file.** When the record has no date,
   the file's own expiry is now shown; Renew still writes the record.
4. **Completing a GRO process flashed the whole page to a skeleton.** The parent's full reload
   remounted the tab. It is now a quiet refetch of the employee.

## Deviations from the card, stated

- **The renewal reference number is not offered.** The card mentioned an optional reference,
  but there is no field to store it (the prototype keeps it in memory). A field that saves
  nothing would be worse than none.
- **View and Download both open the same short-lived link.** Presigned GETs are cross-origin,
  so the browser ignores a `download` attribute.
