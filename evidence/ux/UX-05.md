## The problem

The sidebar was `hidden … md:flex` and the header's only mobile element was a
static text label. Measured before touching anything, at 375×812:

```
navLinksInDom: 13
navLinksVisible: 0
```

That is not a degraded experience — it is a product with **no navigation at all**
below 768px. It was the last blocking finding from the audit.

Second defect, same class: `DialogContent` had **no max-height and no overflow**.
It is `position: fixed`, so anything taller than the viewport was simply
unreachable — the page cannot scroll a fixed element. Measured on the
integrations form at 375×560:

```
submit button bottom: 714px   (viewport height 560px)
```

The submit button sat **154px below the visible viewport** with no way to reach
it. Worst on a phone, but a short laptop window did it too.

## What shipped

- **`components/app-nav.tsx`** — the thirteen permission-gated links, extracted
  from the shell. The sidebar and the sheet render **the same component**. The
  alternative was a second copy of the link list, which drifts the first time a
  gate changes — and the drift would be invisible on whichever surface the person
  making the change wasn't looking at.
- **`components/mobile-nav.tsx`** — the sheet, built from Base UI's Dialog
  **primitives**, not by restyling our `DialogContent`. That component hard-codes
  `top-1/2 start-1/2 -translate-x-1/2 rtl:translate-x-1/2`, and tailwind-merge
  treats `rtl:translate-x-*` as a different group from `translate-x-*`, so an
  override would have dropped the LTR transform and silently kept the RTL one.
- **`ui/dialog.tsx`** — `max-h-[calc(100dvh-2rem)]` + `overflow-y-auto`.
  **`dvh`, not `vh`**: on mobile browsers `100vh` is the viewport with the URL bar
  retracted — taller than what you can see — so a `100vh`-capped modal still hides
  its own footer.
- **15 dialog form grids** → `grid-cols-1 sm:grid-cols-2` (two ~150px columns at
  375px otherwise). The card said 14; there were 15.
- **`ui/data-table.tsx`** — the horizontal scroll container is now a focusable
  `role="region"` with a name (see WCAG note below).

## The bug this card produced, and the fix

Closing the sheet in the link's `onClick` **cancelled the navigation entirely**:
the sheet closed and the URL never changed. Bisected rather than guessed — the
*identical* link rendered by the same `AppNav` in the desktop sidebar navigated
fine, which ruled out the extraction and pointed at the close.

Cause: `next/link` calls `startTransition(() => router.push(href))`, and closing
in the same click unmounts the subtree that owns that pending transition, so it
is discarded. Fixed by closing on **pathname change** — after the route commits —
which also covers back/forward and programmatic navigation.

### A measurement I could not trust, and said so

I tried to measure how long the sheet stays up after a tap, and got 999, 1000,
3999, 5001, 6000 ms — every value a multiple of ~1000. That is Chrome clamping
`setTimeout` in a non-foreground tab, not the app. The one reading taken while
the tab was focused, on a production build, was:

```
url committed:  18ms
sheet removed: 171ms   (= the exit animation)
```

I also built and measured a deferred-close variant (`setTimeout(…, 0)`) to see if
it dismissed sooner. The instrumentation **could not distinguish the two**, so I
did not ship the timer: an unmeasurable micro-optimisation is not worth a magic
`setTimeout` in the component. Recording the attempt because the numbers look
damning until you notice they are all multiples of a second.

One thing worth knowing regardless: the destination page's first render blocks
the main thread, and **no close mechanism can paint through that** — including a
synchronous one.

## Two things fixed beyond the card

1. **Today's rows at 375px.** The fixed date block squeezed titles to ~180px, so
   every row read as an ellipsis (`…r — Rajesh Kumar`). The row now stacks below
   `sm`; nothing is dropped, it reflows. Titles render in full.
2. **WCAG 2.1.1 on table scroll regions.** A container that scrolls horizontally
   must be keyboard-reachable; ours had no `tabindex`, so on Employees **205px of
   columns could not be reached by keyboard at all**. Fixed in `DataTable` —
   focusable + `role="region"` + a name — rather than on the twelve raw tables,
   because UX-03c migrates them all onto that component.
