### The People screen, piece by piece

**Header:**
- "People", with a summary line: "39 employees · sorted by the document that expires first". It
  becomes e.g. "· Passport expiring in 0–7 days" when filtered.
- **Export register** is shown disabled with a "Soon" marker, since no API exists yet.
- **Add person** is shown to `employee.create` holders.

**Filter row:**
- a search box (280px), matching English and Arabic name, position, client and nationality name
  or code through `@hr/text`'s Arabic fold;
- Client, Document and Time-left selects (200px each);
- **Clear filters**, shown only while a select is narrowed, as in the prototype.

**Document filter:**
- Iqama, Work permit, Employment contract and Passport are live.
- **Medical insurance and Driving licence are shown disabled, "· soon"**, because those dates
  aren't stored yet.

**Table:**
- The prototype's 2.2 / 1.5 / 1.4 / 1.3 / 1.5 fr + 40px grid.
- Columns: Employee (avatar, English name as the link, Arabic name beneath in RTL aligned left),
  Client, Position (with nationality via `Intl.DisplayNames`), Iqama expiry (Gregorian plus a
  small Umm al-Qura Hijri line; Saudis show "No expiry"), First document due (chip plus document
  name; the header becomes "{Document} expiry" when one is filtered), chevron.

**Rules:**
- **Ordering:** soonest document first.
- **Chip colours:** red when overdue or ≤7 days, amber ≤14, grey ≤30, faded beyond.
- **Paging:** 50 per page, with the footer shown only when there is more than one page, as in
  the prototype.

**Add a person** (540px):
- Full name and Name in Arabic, then Position, then Client company and Nationality (the
  prototype's ten, stored as ISO codes), the Muqeem hint, Cancel and Add person.
- On success, as the prototype does: the list moves to the new person's company, filters are
  cleared, and a toast reads "{name} added to {client} · identifiers still pending."

## Deviations, each deliberate

- **People with no dated document stay in the list**, last, with "—". This was raised on the
  card. The prototype drops them; here that would hide **21 of 39** real employees (the Saudis
  in the seed).
- **The Arabic name is required.** The prototype marks it optional, but the API stores names in
  both scripts (`bilingualTextSchema`). The error says so.
- **Hijri is Umm al-Qura** (`@hr/dates`, ADR-005), not the prototype's arithmetic calendar,
  which can be a day off.
- **The filters carry `aria-label`s, not visible labels.** The prototype has none, and ADR-012's
  pixel-exact rule postdates UX-13's visible labels.
- **On a phone, the header actions wrap under the title.** The prototype is desktop-only; at
  375px its row squeezed the summary into an 80px column.
- **The client filter is client-side now** (UX-12 had moved it server-side). The document and
  time-left filters need every person's dates in the browser anyway, and `/employees` is
  unpaginated.

## Bugs caught while verifying

- **Equal columns.** All five columns rendered at 189px: a `<col>` ignores `calc()`. They now
  take their fr share of 96%, and Chrome spreads the remainder proportionally, which measures
  exact.
- **A 32.5px header.** Collapsed borders split the first row's top border into the header; the
  table now uses separated borders on the cells.
- **"0–7 days days"** in the summary. The band label already said "days"; the message now
  takes the bare range, as the prototype's does.
- **"Sept".** en-GB prints a four-letter September. The date is now day + en-US short month +
  year, the prototype's "25 Sep 2026".
- **The Arabic name sat right-aligned.** The prototype has `direction: rtl; text-align: left`,
  i.e. the END edge of an RTL box. It now uses `text-end`.
