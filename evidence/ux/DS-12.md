### Per-kind rules (what each control may do)

| | Assignee picker | Snooze (+7 days) | Resolve |
|---|---|---|---|
| Procedure | `gro.process` | `gro.process` | GRO status control (legal next steps only; expiry capture on completion) |
| Request | **shown, not editable**: the API only changes a request's assignee together with its status (REQ-03 `process`) | `request.update` | "Open request" → `/requests?r=` |
| Task | `task.update` | `task.update` | Mark done |

**Deviations from the prototype:**
- No portal tag: nothing stores which portal an item uses.
- The band notes are this product's own wording. The prototype's "statutory fines accrue
  daily" and "portals close 15:00 Thursday" are facts nothing here has verified.
- A **No due date** band is added.

## Bugs caught while verifying

1. The assignee column (132px, the prototype's width) truncated "Unassigned" and full names
   ("Turki Al-…"). It now shows the **first name** over the role, as the prototype does, and
   no avatar when unassigned.
2. A false alarm worth recording: my first Arabic search "didn't filter". The script had typed
   into the header's disabled global search, which comes first in the DOM. Typed into the
   queue's own box, search narrowed 26 → 3 as SQL says.

## Notes and follow-ups

- **Reassigning a request without a status change** needs an API change (REQ-03's `process`
  ties the two together). It is filed as a follow-up card in the backlog.
- Seeded requests share their first 8 id characters (`a0000001-…`), so several show
  `#A0000001` as their reference. Real ids are random v4 UUIDs; this is a seed artefact.
- Task audit entries carry no record id: AUDIT-06 added ids for employee, document,
  GRO-process and request writes only.
