## What changed

### API

| File | Change |
|---|---|
| `@hr/contracts` `audit.ts` | Query: `resources` (comma-separated, 1–50 types) and `q` (1–100 chars). Entries gain `resourceId` (AUDIT-06's record id, `null` when not recorded). New `auditSummaryQuerySchema` (`from`) and `auditSummaryResponseSchema` (`{ eventsToday, actors }`); both exported from the index |
| `audit-query.service.ts` | `resources` → `resource IN (…)` (AND with the others). `q` → case-insensitive `contains` over action OR resource. `summary(from)` → entries since `from` (default UTC midnight) + distinct non-null actors |
| `audit.controller.ts` | `GET /audit/summary` (`audit.read`), parsed with zod (400 on a bad query) |
| `test/isolation/endpoint-registry.ts` | `GET /audit/summary` → `staff` |
| `test/audit/audit-trail.e2e-spec.ts` (new) | 7 cases, below |

**The 7 tests:**
1. `resources=` returns both listed types and **not** the unlisted one.
2. `q=` matches the action case-insensitively (ARCH → "Archive"), and the record type
   (trail-gam).
3. `q=` composes with `resources=` and the cursor: two pages, no overlap, **every row one of
   the listed types and matching**, `nextCursor` null at the end.
4. Entries carry `resourceId` (`null` here).
5. A malformed query → 400 (empty `resources`, a 101-character `q`).
6. Summary keys are exactly `actors`, `eventsToday`; counts ≥ the seeded rows; `from` in the
   future → 0.
7. Summary: Auditor 200, HR officer 403, client rep 403, anonymous 401.

**Proven red first:** all six original cases failed before the change. One of them
(composition) **passed by accident** at first: the unknown parameters were ignored, and any
two pages of 2 satisfied it. It was tightened (every row must be a listed type and match)
until it failed, then the change made it pass.

## Notes

- **The tiles count test traffic too.** The dev database holds every e2e run, so "Actors on
  record" (695) is mostly deleted e2e helper accounts, shown as `#xxxxxxxx` (UX-10b's
  designed fallback). Production numbers will be real people.
- Text search uses `ILIKE` over every row. That is fine at this volume; production will want
  a trigram index (noted in the card's risks).
- The `packages/contracts/src/index.ts` prettier warning predates this card (its HEAD version
  fails the same check), so it was left alone.
