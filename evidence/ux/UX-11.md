## 1 · Active nav state

One change in `AppNav`, which both the sidebar and the mobile sheet render — the
UX-05 extraction paying for itself; a second copy would have drifted on whichever
surface nobody was looking at.

Measured on the sheet at 375px:

```
active   aria-current="page"  font-weight 500  bg oklch(0.97 0 0)
other    (no attribute)       font-weight 400  bg transparent
```

Colour is **not** the only channel — the weight change carries the state on its
own, so it survives a greyscale render (1.4.1).

Nesting is handled by `pathname === href || pathname.startsWith(href + '/')`. The
separator is load-bearing: a bare `startsWith` would light `/portal/company` up
for a future `/portal/companies`. Verified on a detail route:

```
/ar/employees/e0000001-…-000000000009  →  aria-current on /ar/employees   (exactly 1)
```

Across **all 14 screens an hr_officer reaches, in both locales**: exactly one
`aria-current` match each (table below).

## 2 · The skip link — and the trap in the obvious implementation

`sr-only` + `focus:not-sr-only` is the idiom everyone reaches for, and it is
wrong here: `not-sr-only` sets `padding: 0`, and under a `:focus` variant that
outranks the plain `px-4 py-2`. **Measured** — the revealed link came back
**91×20 with no padding at all**. Parking it off-screen with a transform instead
gives `36px` high, padded, in both states.

Proven to actually skip, with real keys:

```
body → Tab → Tab           active = <a href="#main-content">, y = 12 (revealed; parked y = -68)
       → Enter             active = <main id="main-content">, hash = #main-content
       → Tab               active = <button>تحديث</button>, insideMain = true
```

`tabIndex={-1}` on `<main>` is what makes that work. A hash link to a
non-focusable target scrolls and leaves focus behind, so the next Tab returns to
the nav — the failure mode that makes half the skip links on the web decorative.

Focusable elements before `<main>` on `/ar/today`: **18**, of which 17 are the nav
and header. Every navigation used to re-tab all of them.

## 3 · Calendar agenda rows (the Level A fix)

`<li onClick>` → a real `<button type="button">`, but **only for rows that do
something**:

```
16 agenda rows   →   2 buttons (own events, canUpdate)   14 plain divs
                     0 <li> with an onclick handler
```

The 14 read-only projections of Task/Request/GRO deadlines stay plain markup
rather than becoming focus stops that do nothing — the usual way a keyboard
"fix" makes a page worse.

programmatic `.focus()` reports `false` and paints nothing):

```

```

Escape from the editor returns focus **to that button** — a round trip that
previously had nowhere to land.

### Harness limit, stated rather than papered over

Enter/Space could not be driven onto the button through the browser harness. Its
key events arrive trusted but incomplete:

```
{ key: "Enter", code: "", keyCode: 0, trusted: true }   → keydown fires, no click
{ key: "",      code: "", keyCode: 0 }                  ← what "space" arrives as
```

Chrome's default activation keys off `keyCode`, so no click is synthesised; the
same gap is why arrow keys do not scroll a focused region here (Tab works — the
focus manager does not need the code). Activation was therefore confirmed by
mouse, and the keyboard guarantee rests on the element being a real `<button>`
rather than on a hand-rolled key handler. Recorded as a landmine.

## Beyond the four: keyboard-unreachable scroll containers

UX-05 fixed this in `DataTable`. The screens that are **not** lists never
migrated and kept the defect. The tab stop had to go on `<Table>`'s own
container, not on the border wrapper each page draws around it — putting it on
the wrapper produces a focus stop that scrolls nothing.

Measured at 375px, content that was reachable by mouse and by nothing else:

| Screen | hidden px |
|---|---|
| `/candidates` pipeline board | **1061** |
| `/expiry` bucket table | **351** |

`role="region"` is applied only when a name is supplied — an unnamed region is
worse than none. `/reports` names its container after the report
(`aria-label: "Workforce"`), `/expiry` points at its bucket heading, `/audit`
at the page title.

Trade-off taken knowingly: the tab stop is unconditional, so at desktop widths
where nothing overflows it is a stop that does nothing. Detecting overflow would
mean a `ResizeObserver` per table; `DataTable` set the unconditional precedent in
UX-05 and consistency won.

## The bug this card found by measuring

`/ar/calendar` pushed the page **54px sideways at 375px**. I assumed it was mine —
a `<button>` is not `display: flex` by default, and that was the risk written into
the card. It was not. Stashing the branch and re-measuring the untouched screen:

```
baseline (git stash):  overflow = 54px
```

The cause was the month navigation row: `min-w-64` reserved a fixed 256px for the
month label so the arrows stop moving as it changes width, making the row 413px
inside a 343px column. Pre-existing, and missed by the UX-05 sweep. The
reservation is kept from `sm` up, where there is room for it. Now 0px, and the
agenda title also gained `min-w-0 … truncate` so a long title cannot re-open it.

## Not done, deliberately

- **No route-change live region.** Announcing navigation needs its own decision
  with next-intl + the App Router; a badly-scoped one is worse than none.
- **No automated axe harness.** That is test infrastructure, and a separate card.
- **`/audit` not visually verified.** Both roles that can read it are MFA-gated
  with no enrolled seed user (AUTH-06), and reaching it means enrolling TOTP and
  clearing it afterwards. Its change is the same one-line `<Table label>` swap
  verified on `/reports` and `/expiry`; typecheck, lint and build cover the rest.
