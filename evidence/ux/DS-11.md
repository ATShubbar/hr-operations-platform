# DS-11 — the Client record's Requests, Open work and Hiring tabs — Evidence

- Date: 2026-10-04
- Task card: `BACKLOG.md` → DS-11 (DS epic, ADR-012)
- Status: done
- Commit: `DS-11: the Client record's Requests, Open work and Hiring tabs`
- Scope: `apps/web` only. **No API change**: requests, GRO processes and tasks already filter
  by `clientId`, and candidates are filtered on the page.

## Owner decision (with this card)

**Open work lists procedures AND tasks**, not procedures only (my recommendation). Tasks show
as the viewer can see them: `task.read-all` holders see every task, everyone else only the
ones they created or are assigned to. The tab says so. The Overview's Open items tile stays
procedures-only, so it is the same number for everyone.

## Source

The prototype's Client record tabs (`design/…dc.html` lines 2178–2259; data `crReqs`,
`crWork`, `crHiring`, `crCands` near line 4989):
- **Requests:** type, "ref · name · submitted · SLA", a status badge; the row opens the request;
- **Open work:** title, "ref · meta", due + Hijri, Resolve;
- **Hiring:** a Pipeline card (a bar per stage + Open board) beside a Candidates card.

## Bugs caught while verifying

1. Open work's subtitle said it held "procedures, requests and internal tasks", but requests
   have their own tab. It is reworded.
2. "Visa & mobilisation · Soon" wrapped inside the prototype's 118px label column. "Soon" now
   sits where that row's (always empty) bar would be, and every row is one line (16px each,
   measured).
3. Candidates were in API order; they now follow the board's column order.

  DS-09.
