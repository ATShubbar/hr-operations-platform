screening and offer → interview. Same endpoint (`POST /candidates/:id/stage`), same
permission (`candidate.advance`), still audited as before. `hired` / `rejected` /
`withdrawn` stay terminal: a hired candidate already has an employee record (REC-05), so
there is no way back from it.

- `applied → applied` is refused (400);
- screening → applied works; offer → screening (two back) is refused (400);
- the GRO officer, who holds `candidate.advance`, can step back (offer → interview);
- rejected → screening is refused (400); hired → offer is refused (400).

**Proven red first:** before the workflow change the new case failed (`expected 200 "OK",
got 400`). The other 9 cases passed. After the change: 10/10.

## Bugs caught while verifying

1. **A quick drag was refused, by a real mouse.** The column decided legality from React
   state (`dragId`), but the first `dragover` can arrive before React re-renders after
   `dragstart`. A column that doesn't cancel that event never gets the drop. The harness's
   coarse drag sent exactly one `dragenter` into the target and released with **no
   `dragover` there at all**.
   - Fixed twice over: legality now reads a ref set synchronously in `dragstart`, and the
     column cancels `dragenter` as well as `dragover`, as HTML drag and drop specifies for
     a drop target.
   - Before: 0 drops. After: real-mouse drags land.
2. **DS-08's New request dialog never reset.** It reset in `onOpenChange`, which Base UI
   fires only for the dialog's own gestures, never when the parent sets `open`. So no client
   was preselected, and a half-typed form survived a reopen. Found because the new Open a
   role dialog copied the pattern. Both now reset when `open` turns true; Add candidate too.
   - New request after the fix: "Alpha Trading Co." preselected; a stale title is cleared
     on reopen.
3. "…at Alpha Trading Co.." — the company name ends in a period, so the copy no longer puts
   the client last.
4. The client manager's summary said "3 open roles" while counting a Draft and a Filled
   role; it now says "3 roles".
