# UX-17 — grouped, icon-led navigation — Evidence

- Date: 2026-07-25
- Task card: `BACKLOG.md` → UX-17
- Status: done
- Commit: `UX-17: grouped, icon-led navigation with an identity block`
- Scope: `apps/web` only. **No API change.**

## The source component was rewritten, not copied

Owner supplied a sidebar they liked and approved a live preview of it wired to our data.
As given it failed three of this codebase's own gates:

| In the source | Why it could not ship |
|---|---|
| every row is `<div onClick>` | no keyboard, no role — **WCAG 2.1.1 Level A**, the exact defect UX-11 fixed on the calendar agenda. Here they are `<Link>`s, which also restores prefetch and open-in-new-tab |
| `border-r`, `paddingLeft`, `left:`, `mr-3`, `ml-2/3`, `border-l` | `hr/rtl-safe-classes` rejects physical utilities, and in Arabic the tree guides would draw down the wrong side |
| `dark:` variants throughout | dark mode is deliberately not shipped |

Measured after: **14 real links, zero `div` click handlers**, and RTL mirrors with no
direction-specific CSS.

## Two of its features were dropped, and one has no data

**The workspace switcher.** Staff work across *every* client at once — there is nothing to
switch between, and a picker would misdescribe how the product scopes data. Its slot now
carries who is signed in: name and role, from `/auth/me` (real since UX-10b).

**The ⌘K search row.** The UI/UX epic ruled a command palette out — 17 screens do not need
one, and a Latin mnemonic is a poor primary affordance on an Arabic keyboard. A dead `⌘K`
chip would have re-opened a settled decision.

**Collapsible children — the component's headline feature — has nothing to nest.** Our
routes are flat. Nothing was invented to fill it.

**No badge shipped.** The preview wired one to unread notifications; it is not here. The
bell already owns that count and sits in the same viewport, so a copy on *Today* would be
duplication — and worse, mislabelling, since Today is a work queue and not an inbox. The
row markup takes a badge the day a count exists that is genuinely about a screen.

## The grouping is editorial, and the code says so

The routes are flat and imply no hierarchy. `Clients` / `Operations` / `Recruitment` are a
judgement about how the work divides, maintained by hand — a new screen that lands in no
group is a decision, not a default. That is written into the component, not just here.

**Today sits above the groups**, not inside one: it is the whole queue, not a category of
it. Administration (Reports, Staff users, Audit, Settings) sits at the foot behind a rule.

**An empty group renders nothing** — no heading left standing over an absent section:

| Role | Groups | Links |
|---|---|---|
| hr_officer | Clients · Operations · Recruitment | 14 |
| finance | Clients · Operations | 10 — **no Recruitment heading at all**, no GRO, no Google Calendar |
| recruiter | Clients · Operations · Recruitment | 13 — **no GRO** (matrix exclusion flows through) |
| client_admin | *(none)* | 5 — portal surface only; a heading over one group is chrome |

## The bug the change introduced, caught by measuring

The nav now ends in a footer group pinned with `mt-auto`. The sidebar had no
viewport-height box, so "bottom" meant the bottom of the **page**:

```
before   aside height 2243px   →  Settings sat 2243px down a long screen
after    aside height  800px   →  Settings bottom 792 of an 800px viewport
```

Fixed with `md:sticky md:top-0 md:h-dvh` on the aside and `overflow-y-auto` on the nav, so
the sidebar owns its own scroll.

## Both surfaces, one component

`AppNav` still renders the desktop sidebar and the mobile sheet (the UX-05 rule — a second
copy drifts, invisibly, on whichever surface nobody is looking at). The sheet keeps its
own row sizing:

```
sheet rows: every link 44px (WCAG 2.5.5)   14 links   3 headings   fits the sheet   0px overflow
sidebar:    260px (was 240 — the icon column and identity block need it)
            no label truncated at that width, measured via scrollWidth vs clientWidth
```

`aria-current="page"` survives from UX-11, on exactly one link per screen, in both surfaces.
